# zhilian_sales_summary API 观察记录

来源：用户提供的 API 节点截图。没有 API OpenAPI 文件、服务源码、真实端点或成功调用记录。

## 截图中的服务描述

只读查询门店销售报表，按日期、商品和指标返回金额及数据依据。sales 为销售额，returns 为报表退货额，net 为净销售额。不查询库存、利润或退款到账。人工人效与成本尚未实测，相关 0 值是占位，不代表测量结果。

## 已观察入参

| 截图字段 | 观察到的配置 | 目标绑定或待确认事项 |
|---|---|---|
| X-Zhilian-T… | 第一行鉴权参数，界面名称被截断 | 保留平台已有授权配置；完整名称未确认，仓库不保存其值 |
| from | 固定输入 2026-09-01 | 引用解析查询JSON.startDate；确认日期格式与边界 |
| to | 固定输入 2026-09-30 | 引用解析查询JSON.endDate；确认是否包含当天 |
| product_qu… | 字段名被截断，截图中值为空 | 完整名称及空值含义待查；若接收商品名称，引用 productName |
| metric | 固定输入 sales | 首先调通 sales；自动选择指标需扩展解析逻辑 |

不要擅自将截断字段补全为 product_query 或某个鉴权 Header 名称。必须打开服务参数说明核实。

## 已观察输出

| 名称 | 类型 |
|---|---|
| success | boolean |
| answer | string |
| dataset_id | string |
| source_note | string |
| errorMsg | string |

API 已提供 answer 文本，成功路径可直接引用并展示来源，不一定需要再增加大模型整理节点。若再用模型整理，必须禁止补写返回中不存在的金额、币种、单位或统计口径。

## 必须确认

- 服务真实 URL、请求方法、鉴权 Header 的完整名称及访问范围。
- 参数是否另有组织、门店或租户等必填配置。
- 空商品名称是否真的表示全部商品，还是参数错误或其他含义。
- 是否支持明细、分页、多商品、三个指标一起查询。
- from/to 的日期包含关系与时区。
- success=false、无匹配记录、业务异常和系统异常的真实返回样例。
- source_note 和 dataset_id 是否可以直接展示给最终用户。

## 界面其他设置

截图中“动态服务域名”为关闭状态，异常处理为“不重试／中断流程”。这些只代表截图时的配置，不能代替服务契约。当前方案先沿用已配置地址；是否需要动态域名由实际服务部署决定。
